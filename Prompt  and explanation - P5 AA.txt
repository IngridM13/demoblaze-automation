PROMPT USED

  User Journeys, and a deliberate Negative Test for the checkout form.                                                                                                                                                                     
  Note: The negative checkout test is marked with test.fail() intentionally                                                                                                                                                                
  because it exposes a known bug (lack of credit card validation in the                                                                                                                                                                    
  frontend), causing a timeout when waiting for the error message.                                                                                                                                                                         
                                                                                                                                                                                                                                           
  Input Data: Please explore the current workspace and locate the recent                                                                                                                                                                   
  test execution outputs (look into directories like playwright-report/,                                                                                                                                                                   
  test-results/, or allure-results/, and read the relevant .json, .html,                                                                                                                                                                   
  or log files).                                                                                                                                                                                                                           
                                                                                                                                                                                                                                           
  Task: Based on the files you analyzed in the workspace and the provided                                                                                                                                                                  
  context, generate an Executive Summary intended for stakeholders and the                                                                                                                                                                 
  development team. The summary must strictly include the following sections:                                                                                                                                                              
                  
  Failed Tests & Possible Root Cause, Detected Patterns, Action Suggestions.                                                                                                                                                               
                  
  Format & Delivery: Generate the output as a fully formatted, standalone                                                                                                                                                                  
  HTML file (executive-summary.html) and save it in the root directory.
  Include clean, professional CSS styling so I can open it in a browser                                                                                                                                                                    
  and save it as a high-quality PDF.                                                                                                                                                                                                       
                                                                                                                                                                                                                                           
  Constraints: The output must be well commented and follow best practices.                                                                                                                                                                
  Do not add unnecessary sections. 




WHY THE PROMPT WAS WRITTEN THIS WAY
  -------------------------------------
  Role assignment: Giving the model a specific role (QA Lead + Release
  Manager) anchors the perspective and vocabulary of the output. Without
  it, the model may produce a generic technical log summary rather than
  stakeholder-facing language with business context.

  Explicit context about test.fail(): Without this, the model might
  classify the negative test as an unexpected failure and misdiagnose its
  root cause. The note prevents a false positive in the analysis and
  ensures the intentional design decision is reflected accurately.

  Directing the model to read real artifacts: Telling the model where to
  look (allure-results/, playwright-report/) grounds the output in actual
  execution data rather than invented or hallucinated results. This is the
  difference between an audit and a fabrication.

  Structured section requirements: Listing the exact sections (Failed
  Tests, Patterns, Action Suggestions) prevents the model from deciding
  the structure on its own, which could produce an inconsistent or
  incomplete report depending on what it considers relevant.
                                                                                                                                                                                                                                           
  Format specified as HTML with CSS: Asking for a standalone HTML file                                                                                                                                                                     
  with print-ready styling defines the delivery format precisely, avoiding                                                                                                                                                                 
  a markdown file or plain text that would require additional tooling to                                                                                                                                                                   
  convert to PDF.                                                                                                                                                                                                                          
                                                                                                                                                                                                                                           
  Constraints on brevity: "Do not add unnecessary sections" counters the                                                                                                                                                                   
  model's tendency to pad responses with boilerplate. It keeps the report
  focused on signal, not volume.
